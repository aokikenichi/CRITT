# CRITT Museum — 工程04 Codex実装指示書 v1.0

## 0. 作業の目的と今回の完成物

**BEYOND THE BOUNDARY** の作品001〜010（α版として仮OK済み）を、一つの**歩いて巡れる仮想美術館**として体験できるようにする。

来館者は入口ホールから、通路で接続された5展示室（各2作品）を**実際に移動**し、展示物に近づくとその作品の既存インタラクティブHTMLを鑑賞できる。作品鑑賞を閉じると**同じ展示室の、入場直前の位置と向き**に戻る。

今回の納品物は、**10作品すべてを体験できる、統合回遊型のα版HTML**と、その検証結果。ラフな館内地図だけ、ページリンク集だけ、技術デモだけで「完成」と報告してはいけない。

ユーザーは10作品をすでにα版として仮OKしている。**芸術的な再審査・原画再承認を繰り返し求めない。** まず全体を一巡できるものを作り、修正はユーザーの全館体験後に進める。旧版比較・不具合は既存の記録を保持する。

## 3. 実装する展示体験

### 3.1 建築として一体の空間

`museum/gallery.html`を新しい館内回遊入口とする。`museum/js/gallery.js`, `museum/css/gallery.css`などは必要に応じ追加。

- **入口ホール → 通路 → 第1〜第5展示室**を一つの連続した3D空間として配置する。通路に戻り、別の展示室へ徒歩で移動できる。クリックによる部屋切替や単なるスライドショーを「歩ける館内」と呼ばない。
- 5室は大きさ・照明・造形・展示台の表現で違いを持たせる。ただし過剰な装飾や汎用ゲームUIにしない。静謐な現代アート美術館らしい建築空間、作品の存在感、視線の奥行き、陰影、サイン計画を重視する。
- 各室に作品2点の**鑑賞入口となる展示物またはポータル**を設ける。作品番号・題名、適切なプレビュー、近づいたときの鑑賞案内。単なるメニュー一覧・黒い箱・ラベルだけの3D展示室にしない。
- 作品への導線は「近づく → 案内表示 → Eキー／クリック／タップで鑑賞」。作品HTMLのリアルタイムレンダリングを壁テクスチャとして多数同時起動しない（GPU・入力競合を避ける）。
- 館内に現在地表示、展示室名、簡潔な操作方法、退出／一覧導線を持たせる。小さなテキストと操作の競合を避ける。

### 3.2 館内の操作

- PC：WASD／矢印で移動、マウスドラッグで見回し、E／Enterで近くの展示を鑑賞。移動の速度は調整可能、壁を通過しない、開口部を通れる。Esc／キー割り当ては作品内モーダルと衝突させない。
- モバイル：タッチによる移動と見回し、およびタップで作品を開く操作を用意。タッチだけで展示室間を移動できること。
- 自由回遊と**館内Autoツアー**を用意。Autoは入口から5室を順に歩き、各作品の前で停止・作品名を表示する。**作品HTMLを自動起動しない**（あくまで館内ツアー）。一時停止／再開／Manual切替を実装。
- アクセシビリティ：地図／展示室ショートカットも提供する（歩行の代替導線）。キーボードフォーカス、文字コントラスト、`prefers-reduced-motion`、WebGL不対応時のHTMLリスト代替を考慮する。3D歩行不能でも10作品に到達できる。

### 3.3 既存HTMLへの入退場（最重要）

- 鑑賞開始時は**オーバーレイ型の全面鑑賞ビュー**を推奨。既存`work.html` / `review-work.html`を同一オリジンのiframeに開き、作品内部の既存操作を尊重する。二重iframeになる場合の動作とモバイルUIを検証。
- **「展示室に戻る」固定ボタン**を明示し、作品内部のモーダルEscを奪わない。閉じたら同じ展示室・同じ位置・同じ視線方向へ戻る。カメラを入口に毎回リセットしない。
- 鑑賞中は館内のキー／ポインタ入力を停止し、館内の描画ループも必要に応じ休止。戻ったらiframeを破棄してWebGL/GPUを解放し、館内にフォーカスを復元。
- ブラウザの戻る操作で鑑賞から館内へ戻れるようにする場合はHistory APIを正しく処理する。リロードやURL直打ちからも安全に復帰できるようにする。安易な `postMessage('*')`、任意の外部URLをiframeで開く実装は禁止。
- 作品001〜008で`review-work.html`内の「一覧へ」が比較ページを指していても、統合館内からは**固定の「展示室に戻る」**で回帰できる。

## 5. 合格条件（自動テスト＋実ブラウザで証拠を残す）

1. `museum/gallery.html`をローカルHTTPで開くと入口ホールが表示され、5室の相互移動を実際の歩行で行える。
2. 第1〜第5展示室の各2作品、**001〜010の10/10**を鑑賞開始できる。作品開始URLと描画・操作をそれぞれ確認。
3. 10作品とも「展示室に戻る」後、前の館内座標・向きが保持される。少なくとも001、005、009、010で明示的に検証する。
4. 館内Autoで5室・10スポットを巡る。停止・再開・Manual復帰が動く。
5. PC（例 1440×900）／モバイル幅（例 390×844）で表示・移動・入退場・戻る動線を確認。可能なら実機タッチも。未確認範囲は明示。
6. 001/002複合ラボ、008架空データ、009/010既定試作、原画0点など既知の制限を正しく表示し、無断で採用版を変更しない。
7. GitHub `main`、PR #1／#2のheadは変化なし。**作業PRのみ**作成。CI等で既存CRITTのリンク・ビルドに回帰なし。
8. テスト時のスクリーンショット：入口、通路、第1・第3・第5展示室、作品鑑賞中、展示室への復帰、モバイル画面。可能なら全館俯瞰図も。
9. `museum/GALLERY04_IMPLEMENTATION_REPORT.md`、`museum/GALLERY04_QA.md`、`museum/GALLERY04_PENDING.md`を追加。**工程名は「統合回遊実装／工程04」**と統一し、既存STEP04回収記録の上書きを避ける。

## 6. Codexの完了報告フォーマット

次の5項目だけを簡潔に報告する：

1. **できたもの**：館内回遊、5室、10作品入退場、Auto、モバイル。
2. **実際のテスト結果**：PC／モバイル、10作品の成功/失敗、戻り位置保持。
3. **未完了・既知の制限**：芸術的な修正とは切り離す。
4. **差分とPR URL**：base/head、変更ファイル、`main`未変更を確認。
5. **ユーザーが次にすべきこと**：**まず統合館内を通して体験する**。改善の議論はその後。

**品質上の注意**：この工程の成功条件はドキュメントや比較ページの完成ではない。実際に歩ける館内と、既存10作品への入退場が動くことである。レビューのために未完成部分を残すのはよいが、壊れているものを黙って完成扱いにしない。

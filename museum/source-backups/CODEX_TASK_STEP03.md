# Codex実装指示：CRITT Museum α版 共通フォーマット（工程③）

- 発行：2026-10-27
- リポジトリ：`aokikenichi/CRITT`（既存のGitHub Pagesサイト）
- 作業範囲：**工程③「共通鑑賞UIと美術館入口の技術的骨格」だけ**
- 主目的：異なる方式で制作された作品を壊さず、一つの美術館で鑑賞できる共通インターフェースを実装する。
- **禁止：`main`へのマージ、GitHub Pages公開、既存CRITTトップページの変更、作品の大量再生成。**

## A. 入力資料と優先順位

このZIPを作業環境へ展開し、同梱された次の実体を使う。

1. `INPUT/WORK_INVENTORY.md`：どの作品が現物確認済みか。存在判定では最優先。
2. `INPUT/artworks.json`：作品001〜010の**暫定台帳**。タイトル・版数は確定情報ではない。
3. `INPUT/CRITT_Museum_Work09_Gravity_Panorama_Rebuild_v0.5.html`：作品009のHTML実体（保留中の試作）。
4. `INPUT/CRITT_Museum_Work10_Final_Boundary_v1.0.html`：作品010のHTML実体（試作）。
5. `INPUT/CRITT_Museum_Alpha_Publication_Plan_v0.1.md`：共通UIの理念、将来の公開要件。
6. `INPUT/ASSET_MANIFEST.csv`：取得済みファイルのサイズ・SHA-256記録。
7. `INPUT/CANDIDATE_NOT_ORIGINAL/`：作品009の背景候補。**採用確定原画ではない**。

GitHub `aokikenichi/CRITT` の現況を最初に読み取り確認する。既存の `index.html` 等は変更しない。

**注意：** 001〜008の最新作品HTML本体は入力にない。存在を偽装しない。旧 `critt-museum.html`（古い7展示構成）は今回の001〜010として流用しない。

## B. 今回つくるもの（実装タスク）

### B1. 美術館の共通入口と作品一覧

`museum/` ディレクトリ以下に、既存サイトと独立した静的ページを新設する。

- `museum/index.html`：展覧会タイトル、α試作である説明、作品001〜010の一覧。サイトへ戻る導線。
- 作品一覧：001〜010の3桁ID、暫定作品名、状態（鑑賞可能／試作中／原本未取得）を表示。**001〜008の「鑑賞する」ボタンを有効にしない。** 詳細・収録待ち状態は閲覧できるようにする。
- `museum/work.html?id=009` または `?id=010` で共通鑑賞ページへアクセスできるようにする。IDの入力を検証し、未知のIDなら一覧へ戻す。
- `museum/work.html?id=001`〜`008` は「原本未取得／現在収録準備中」を明示。空の展示を完成済みとして見せない。
- 独自の作品形態をつぶす一律3D化・一律フレーム化はしない。

### B2. 作品009と010を壊さず接続

- `museum/works/009/index.html` に同梱009 HTMLを、`museum/works/010/index.html` に同梱010 HTMLを配置する（著作物の内容を無用に書き換えない）。
- `museum/work.html` の共通シェルから、信頼する同一オリジンの作品HTMLを iframe などで開く。作品自体の描画・キー入力・ポインタ操作を妨げない。操作不可なら薄いアダプタを最小追加し、その差分を記録する。
- 09は**作者評価保留中**、10は**α試作**という状態を明記。作品09の表現を再制作・改善しようとしない。
- 009/010について実ブラウザで描画・動作を検証し、成功した操作と未確認の操作を記録する。旧v3.3/3.4は存在確認不可のため比較対象としない。

### B3. 共通フォーマット

共通シェルには同じ位置・同じ名称で次のUIを配置する。

- 展覧会名と作品ID・作品タイトル、状態表示
- 「作品について」（作品の問い／技法・表示方法／架空作品であること／試作状況）
- 「原画を見る」（元画像の正式な登録がある場合のみ動作）
- 「操作方法」／「作品一覧へ」／「前の作品」／「次の作品」
- UIを隠す（共通シェルが妨げない場合のみ）
- 手動／自動鑑賞について、**作品内部で実装が確認できた場合のみ共通シェルから操作可能にする**。実装状況が不明なら「作品画面内で操作してください」と表示し、動かない共通ボタンを設置しない。

鑑賞中の作品表示領域は可能な限り大きく保つ。共通UIのためにCanvas画面やポインタ操作を潰さない。

### B4. 原画ビューア（機能は実装、虚偽表示はしない）

- 作品メタデータに `originals[]` が**正式採用原画として登録済み**の場合だけ「原画を見る」を有効化する。
- モーダル内で作品画像、画像の説明・来歴、フィット表示、拡大縮小、前後切替、閉じる（Esc、タッチ）を提供。
- 09の `09-A_ground.jpg` / `09-B_suspended.jpg` / `09-C_never_falls.jpg` は**候補素材**。原画に昇格させない。必要なら「制作途中の参考画像」の別リンクへ明示して使う。
- 10の既存スクリーンショットも**原画ではない**。
- 原画ゼロの作品は「原画未登録」と明示し、無効ボタンまたは説明表示。原画があるかのように振る舞わない。

### B5. 技術要件

- GitHub Pagesの `https://aokikenichi.github.io/CRITT/museum/` 配下で動く**相対パス**。ルート絶対パスを安易に使用しない。
- 静的HTML/CSS/JSで動作。サーバーやバックエンドは追加しない。必要な軽量ライブラリは導入理由を記録。
- スマホ対応、キーボード操作、フォーカス・Esc、`prefers-reduced-motion`、明瞭な状態表示。
- 作品009/010のオリジナルHTMLと表示資産は、シェル実装前にバックアップし、改変差分を追跡する。
- 作品台帳は、納品時に `museum/artworks.json` として**公開用表示項目だけ**を整える。元の `INPUT/artworks.json` は記録として維持する。`source_status` 等の不明情報を推測で確定しない。
- `postMessage` を使う場合、許可する同一オリジンとメッセージ種別を固定。未対応作品へ無理なメッセージ制御を加えない。
- 初回の実ブラウザテストは `file://` ではなく HTTP サーバー（例 `python -m http.server 8000`）で行い、`/museum/` のURLと相対パスを確認する。GitHub Pages サブパスのプレビュー試験も行う。

## C. 今回やらないこと

- 001〜008のHTMLを推測で再制作すること（別工程で採否判断）。
- 09/10の造形・画像を「完成」にすること。原画を新しく生成したと装うこと。
- 実在美術館の外部リンク詳細の調査・確定（工程④で実施）。`references.html` は簡易予定表示でも可。
- 本番公開、`main`へのマージ、CRITTトップに「Museum公開済」のリンクを追加すること。

## D. 納品物

作業ブランチ内に、少なくとも次を残す。

```

  index.html

  artworks.json
  css/museum.css
  js/museum-shell.js
  works/009/index.html
  works/010/index.html
  # 必要に応じて assets/ など
```

併せて以下を新規作成：

- `museum/STEP03_IMPLEMENTATION_REPORT.md`：実装範囲、009/010の接続方法、元HTMLの変更有無、原画・Manual/Auto対応可否、既知の制約。
- `museum/STEP03_QA.md`：実行したテスト／結果／失敗／未実施事項を区別して記載。
- `museum/STEP03_PENDING.md`：次工程で必要な001〜008の収録、原画登録、実在施設リンク等の未解決事項。

## E. 受入判定（完了条件）

1. `museum/index.html` がブラウザで開き、001〜010の一覧と状態を正しく示す。
2. `work.html?id=009` / `010` から同梱済み作品を鑑賞できる。作品内のManual/Auto等、確認できた操作が共通UIによって壊れていない。
3. 001〜008は**未収録**と正直に表示し、リンク切れや空白だけの展示をしない。
4. 原画ビューアは正式登録された画像に対して動作する設計があり、原画なしの作品では誤認を生まない。ダミー原画で「完成」と主張しない。
5. PC/モバイルの表示テスト、前へ／次へ／一覧へ、Esc・キーボードでの基本操作を実ブラウザで検証し `STEP03_QA.md` に記録する。テストできない項目は未検証とする。
6. `main`への変更・公開は**行わない**。

## F. Codex終了時の報告形式（最優先）

回答の冒頭に次の4行を必ず記載する。

1. **結果：** 工程③の完了／一部完了／未完了
2. **動くもの：** 009・010に何ができたか（未確認は未確認）
3. **未収録：** 001〜008について何が足りないか
4. **Next Action：** 次の一手を1つだけ（担当者つき）

その後にファイル一覧／QAと作業ブランチ・PRを簡潔に示す。成果を過大評価しない。
